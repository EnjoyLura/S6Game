# 浏览器性能实测

从冒险、副本战斗或招募页的「菜单」打开「性能测试」。开启后顶部显示每秒帧数、帧间隔 P95 和最近一次点击耗时。可返回同一菜单停止采集和导出 JSON。数据只保留在当前页面会话，每类最多保留最近 2,400 条，开启新一次采集时重置。导出包含按钮和界面名称、点击到浏览器第二个动画帧的耗时、按钮处理耗时、帧间隔、战斗更新和界面刷新耗时。

2026-11-22 在同一台机器的 Chrome 无头浏览器中，使用 390×844、2 倍像素密度和 4 倍 CPU 限速，执行优化前后相同的自动化流程。两轮都使用 WebP Q92，采集开关关闭，点击耗时由测试独立记录。点击到第二个动画帧包含一帧采样余量，数据用于同条件比较。战斗和静置各采样约 5 秒，背包和分解各执行 12 次点击。结果不等同于真机测量。

| 压力场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 背包类别切换（200件） | 389.8 / 678.0 ms | 53.2 / 95.6 ms |
| 分解选取（200件列表） | 594.3 / 682.6 ms | 28.7 / 39.6 ms |
| 冒险战斗 | 6.4 ms / 2356 ms / 85 | 6.4 ms / 1333 ms / 46 |
| 副本战斗 | 12.4 ms / 2541 ms / 85 | 6.4 ms / 1156 ms / 48 |
| 背包停留 | 6.4 ms / 1179 ms / 84 | 6.4 ms / 666 ms / 1 |

点击场景依次列出响应中位数和 P95。战斗与静置依次列出帧间隔 P95、浏览器主线程累计任务耗时及布局次数。200 件装备中已锁定与已穿戴装备按游戏规则排除分解。

切换页面只绘制一次，浏览器界面不再刷新隐藏的 Cocos 页。美术图集切片在浏览器中共用短地址，装备列表勾选时仅更新选中状态、材料预览和操作按钮，保留滚动位置。战场布局仅在视口、战场或界面几何变化时重算，血条只在数值改变时重绘，角色脚底位置按纹理切片复用。战斗逻辑、伤害与收益结算沿用现有模型。
