# 第二版界面实装

本轮按第二版效果图合集的26个界面接入可操作界面。实装截图及入口对应见 [第二版实装验收.html](第二版实装验收.html)。概念图和实装截图分别维护，不以概念图冒充运行结果。

浏览器版本使用响应式界面组件叠加 Cocos 实时战场。战斗动作、血条、技能排队、副本波次及结算沿用原模型；按钮、标题、通用弹窗、品质格、五列奖励区、筛选排序及英雄卡片集中复用。文字单独渲染，装备格保持正方形，短屏内容可滚动，横屏游戏区域按竖屏比例收窄。未适配原生安装包的界面升级，原 Cocos 页面作为非浏览器回退保留。

## 页面与入口

| 界面 | 实际入口 |
|---|---|
| 冒险、英雄、招募、背包、副本 | 底部五项导航 |
| 常驻与UP、卡池详情 | 招募页切换；卡池详情按钮 |
| 招募单抽与十连结果 | 两种卡池均可单抽或十连；结果底部保留两种按钮 |
| 资源副本、无尽、每日 | 副本页三个页签 |
| 副本挑战确认 | 对应副本“挑战”，弹窗内选择难度 |
| 挂机奖励、获取奖励 | 冒险“挂机收益”；领取或快速扫荡后显示获得结果 |
| 装备详情、穿戴、升级、突破 | 英雄装备槽／背包装备格；详情“强化”进入独立二级页 |
| 升星、技能、天赋树 | 英雄星级按钮、四个技能、天赋树 |
| 编队与阵型 | 冒险阵型／英雄编队，编队页阵型选择 |
| 分解与小确认 | 背包批量分解、扩容、重置和扫荡等确认操作 |

## 本轮测试配置

- 原有四名英雄保持不变，概念图8人卡池不会自动生成四位没有战斗定义的英雄。卡池概率、保底沿用原配置；常驻券与UP券各自扣除，UP券测试初始60张。
- 背包初始200格，每次扩50格，500金币起逐次增加500；满包新掉落转为现有强化石，不删除原有装备。旧档已有超容量装备全部保留。
- 装备按槽位主属性区分基础／随机属性，普通逐级提升主属性10%，每逢9→10级同时提升随机属性15%，100级封顶；预览和扣费使用同一公式。保留旧装备强化值及已投入材料，避免损失旧档培养。
- 装备效果随机产生：史诗0～1个、传说0～2个，当前测试为攻击或生命+5%，实际计入战斗。旧装备无效果时显示“无”；不增加复杂触发体系。
- 每名英雄15个天赋节点，树干5个、两侧各5个；单点消耗1，分支前置限制。属性、技能效果及第二主动冷却实际生效；重置返还包括旧天赋投入的全部点数。
- 四套独立编队预设，受击率阵型为60/25/15、40/40/20、34/33/33、70/15/15。最多三人，重复和未持有英雄不得加入；副本内更换不回血、不复活、不重置敌人。
- 快速扫荡消耗10体力，按当前检查点的离线公式直接结算30分钟；不会吞掉待领取离线清单。资源、副本次数、成长、阵型、票券与结果均继续经过本地存档校验及事务保存。
- 副本保留原10波小怪加首领波的现行逻辑、每日共享两次和体力恢复。结算关闭不退出战场，支持重新打开结算、再次挑战与显式退出。

上述均为验证数值，不作为正式平衡承诺。资源提示词、图集切片和来源见 [第二版实装资源.json](第二版实装资源.json)。

## 验证与重现

1. `npm ci` 安装验证依赖；本机安装 Chrome 和 Cocos Creator 3.8.8。
2. `npm test` 执行模型与存档回归。
3. `npm run build` 构建并校验浏览器运行文件。
4. `npm run serve` 启动本地游戏；另一个终端运行 `npm run test:ui`。

界面验证使用独立无头浏览器存档，准备已培养英雄和装备的测试状态；不修改用户浏览器的正式存档，也不在正式界面加入测试加钱入口。自动验证真实点击、保存刷新、单抽十连、天赋学习、扩容、入场及结算退出，截取26个界面及三种战斗结算，检查360×640、430×932、768×1024、1280×720四组屏幕尺寸。

## GitHub Pages 发布

用户授权后，执行 `python scripts/publish-github-pages.py`，将已构建并校验的浏览器包发布到独立仓库 `EnjoyLura/S6Game-play`。页面地址为 https://enjoylura.github.io/S6Game-play/ 。运行资源按源码提交号隔离目录，入口通过相对base路径适配项目子路径与版本缓存；发布清单保存SHA256和源码版本，脚本等待线上版本一致才成功。凭据仅从Git凭据助手读取，不写入运行包，不触发Cloudflare。
